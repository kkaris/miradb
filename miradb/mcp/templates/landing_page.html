About this MCP Server

MIRA-DB is a database of compartmental epidemiology models automatically extracted from papers. Each paper's ODEs are extracted with several methods (PDF text, OCR, PubMed Central XML) and converted into ontology-grounded MIRA TemplateModel, together with the parameter scenarios reported in the paper. Browse it at epimodels.io.

Capabilities

  • Find models in the literature: Search papers by title, author, year or grounded concept (e.g. the IDO term for "infected"), and get every extracted model and scenario for a paper.
  • Inspect model structure: See compartments with their ontology groundings, transitions with rate laws, and the ODE system as equations.
  • Edit models: Add, remove or update compartments, transitions, parameters, initial conditions and observables, one change at a time, with every version kept.
  • Transform models: Stratify by age, location or any other key, merge two models, bake in a paper's scenario, and simplify rate laws or parameters, all with MIRA.
  • Compare models: Score similarity, list what differs, and draw the difference as a graph. Concepts are matched through the MIRA domain knowledge graph, so a more specific grounding counts as a refinement.
  • Simulate: Run deterministic ODE simulations using a paper's own scenario, with the server telling the agent exactly which values are still missing.
  • Query anything else: Run read-only SQL for questions the curated tools don't cover.

How the MCP server works

The server exposes 46 tools in six groups. The tool reference lists every tool with its parameters.

🔎 Search & query

7 tools

Papers, extracted ODEs, scenarios, the database schema, and read-only SQL.

🧩 Inspect

5 tools

Model summaries, equations, graph drawings, export as MIRA JSON or Petri net AMR.

✏️ Edit

19 tools

Add, remove or update states, transitions, parameters, initials and observables; set values, annotations, authors and time units.

🔀 Transform

8 tools

Stratify, merge models, apply a scenario, simplify rate laws, tidy parameters, convert counts to fractions.

⚖️ Compare

5 tools

Similarity scores, text diffs, diff drawings, and concept and context comparison with ontology-aware matching.

📈 Simulate

2 tools

Deterministic ODE runs with peak and final-size stats, trajectories and CSV.

A typical session goes from a search term to a simulated epidemic. Each step's output feeds the next:

  1. 1

    Find papers

    returns PMIDs

    Search by title, author, year or grounded concept, e.g. covid or the IDO ID for "infected".

    db_search_publications
  2. 2

    Open a paper

    returns db:984 + scenario IDs

    One model per extraction method, plus the parameter scenarios reported in the paper.

    db_get_publication db_get_scenarios db_get_odes
  3. 3

    Inspect the model

    returns compartments, rate laws, ODEs

    Compartments with ontology groundings, transitions, and which parameters and initial values are still missing.

    mira_get_model mira_get_equations mira_draw_model
  4. 4

    Edit or transform itoptional

    db:984 → ws:90c4… → ws:704b…

    Add a compartment, rewrite a rate law, stratify by age, or merge in another model. Each change returns a new workspace model, so edits chain and the original is never modified.

    mira_add_* / mira_remove_* / mira_update_* mira_stratify mira_merge_models mira_apply_scenario
  5. 5

    Simulate

    returns peak, timing, final size, CSV

    Deterministic ODE run using a paper's scenario, with any overrides on top.

    simulate_model get_simulation
    ↻ If values are missing, the server returns missing_values listing exactly which parameters and initial conditions to supply, and the agent calls again with them.

At any point

Compare models mira_compare_models mira_model_delta mira_draw_model_delta mira_compare_concepts
Export or review the workspace mira_export_model mira_list_workspace
Ask anything else with read-only SQL db_describe_schema db_run_sql

Models are passed between tools by handle, never as raw JSON:

  • db:<id> is a model stored in MIRA-DB.
  • ws:<id> is a model the agent derived in this session (for example by stratifying). Tools that change a model return a new ws: handle and leave the input untouched.

Example Usage

Once connected, ask questions in plain English. The AI agent uses this MCP server to search, inspect and simulate models on your behalf:

🦠 Find and Simulate a Published Model ▼

Ask: "Find a COVID-19 SEIR model for South Africa and simulate the pre-lockdown scenario for 100 days. When does the epidemic peak?"

Behind the scenes, the AI agent runs the following steps using this MCP server:

Step 1: Search the literature

db_search_publications(query="covid", limit=3) 
{
  "total": 1036,
  "results": [
    {"pmid": "38977919", "title": "Integrating socio-psychological factors in the SEIR model ...", "model_count": 5, "scenario_count": 1},
    {"pmid": "32982082", "title": "Simulation of coronavirus disease 2019 (COVID-19) scenarios ...", "model_count": 5, "scenario_count": 0},
    {"pmid": "32706790", "title": "Quantifying early COVID-19 outbreak transmission in South Africa ...", "model_count": 5, "scenario_count": 2}
  ]
}

Step 2: Get the paper's models and scenarios

db_get_publication(pmid="32706790") 
{
  "title": "Quantifying early COVID-19 outbreak transmission in South Africa and exploring vaccine efficacy scenarios",
  "journal": "PLoS ONE", "year": 2020,
  "models": [
    {"model_ref": "db:984", "extraction_method": "xml_extraction", "template_count": 3},
    {"model_ref": "db:249", "extraction_method": "marker", "template_count": 3},
    // ... 3 more extraction methods
  ],
  "scenarios": [
    {"scenario_id": 3, "name": "before_lockdown", "model_ref": "db:984", "parameter_count": 3},
    {"scenario_id": 4, "name": "after_lockdown", "model_ref": "db:984", "parameter_count": 1},
    // ... 2 more
  ]
}

Step 3: Inspect the equations

mira_get_equations(model_ref="db:984") 
{
  "equations": [
    "dS/dt = -I*S*beta*(1 - epsilon)",
    "dI/dt = E*sigma - I*gamma",
    "dE/dt = -E*sigma + I*S*beta*(1 - epsilon)",
    "dR/dt = I*gamma"
  ]
}

Step 4: Try the scenario, and see what's missing

simulate_model(model_ref="db:984", t_end=100, scenario_id=3) 
{
  "status": "missing_values",
  "missing_parameters": ["epsilon"],
  "missing_initials": ["S", "I", "E", "R"],
  "scenario_applied": {"parameters": {"beta": 1.3, "sigma": 3.21, "gamma": 2.27}},
  "hint": "Pass the missing values in `parameters` / `initials`, or pick a `scenario_id` that provides them."
}

Step 5: Supply the values and run

The scenario reports σ and γ as periods in days, so the agent converts them to rates (1/3.21 and 1/2.27), sets ε = 0 (no vaccine) and starts with 0.1% infected:

simulate_model(model_ref="db:984", t_end=100, scenario_id=3, parameters={"epsilon": 0, "sigma": 0.3115, "gamma": 0.4405}, initials={"S": 0.999, "E": 0, "I": 0.001, "R": 0}) 
{
  "status": "ok",
  "sim_id": "9a5612fe5b7c",
  "stats": {
    "I": {"max": 0.119, "t_at_max": 27.0},
    "E": {"max": 0.179, "t_at_max": 25.0},
    "R": {"final": 0.937},
    "S": {"final": 0.063}
  },
  "full_results": "miradb://simulation/9a5612fe5b7c.csv"
}
Result: With the pre-lockdown parameters (R₀ ≈ β/γ ≈ 2.95), infections peak at about 12% of the population on day 27, and about 94% have been infected by day 100. The agent got from a search term to a simulated epidemic in five tool calls, without anyone writing ODE code.
👥 Stratify a Model by Age ▼

Ask: "Take that South Africa SEIR model and split it into young and old age groups."

Behind the scenes, the AI agent runs the following steps using this MCP server:

Step 1: Look at the model's structure and groundings

mira_get_model(model_ref="db:984") 
{
  "compartments": [
    {"name": "S", "identifiers": {"ido": "0000514"}, "context": {"status": "susceptible"}},
    {"name": "E", "identifiers": {"apollosv": "00000154"}, "context": {"status": "exposed"}},
    {"name": "I", "identifiers": {"ido": "0000511"}, "context": {"status": "infected"}},
    {"name": "R", "identifiers": {"ido": "0000592"}, "context": {"status": "recovered"}}
  ],
  "transition_type_counts": {"ControlledConversion": 1, "NaturalConversion": 2},
  "parameters_without_value": ["beta", "epsilon", "gamma", "sigma"]
}

Step 2: Stratify

mira_stratify(model_ref="db:984", key="age", strata=["young", "old"]) 
{
  "model_ref": "ws:06bd5c0ce2fc",
  "compartments": [
    {"name": "S_young", "context": {"status": "susceptible", "age": "young"}},
    {"name": "S_old",   "context": {"status": "susceptible", "age": "old"}},
    {"name": "I_young", "context": {"status": "infected",    "age": "young"}},
    // ... 5 more compartments
  ],
  "transitions": [
    {"name": "t_young", "type": "ControlledConversion", "rate_law": "I_young*S_young*beta_0*(1 - epsilon_0)"},
    {"name": "t_old",   "type": "ControlledConversion", "rate_law": "I_old*S_old*beta_1*(1 - epsilon_1)"},
    // ... plus progression, recovery and between-strata transitions
  ]
}
Result: A new workspace model ws:06bd5c0ce2fc with 8 compartments that keep their ontology groundings, and per-stratum parameters. The original db:984 is unchanged; the new handle can go straight into mira_set_values, simulate_model or mira_export_model (e.g. as an ASKEM Petri net AMR).
💉 Add a Vaccination Compartment ▼

Ask: "Add a vaccinated compartment to the South Africa SEIR model, with people vaccinated at 1% a day, and show me what changed."

Behind the scenes, the AI agent runs the following steps using this MCP server:

Step 1: Add a grounded state

mira_add_state(model_ref="db:984", name="V", identifiers={"vo": "0001376"}, context={"status": "vaccinated"}) 
{
  "model_ref": "ws:90c406ce9bdc",
  "parent": "db:984",
  "operation": "add_state('V')",
  "changes": {"added_state": "V", "hint": "Connect the state with mira_add_transition."}
}

Step 2: Connect it with a transition

mira_add_transition(model_ref="ws:90c406ce9bdc", name="vaccination", subject="S", outcome="V", rate_law="nu*S", parameters={"nu": {"value": 0.01, "units": "1/day"}}) 
{
  "model_ref": "ws:704bdd6023a4",
  "parent": "ws:90c406ce9bdc",
  "operation": "add_transition(NaturalConversion)",
  "changes": {
    "added_transition": {"id": "vaccination", "type": "NaturalConversion", "concepts": ["S", "V"], "rate_law": "S*nu"},
    "added_parameters": ["nu"]
  }
}

Step 3: Diff against the original

mira_model_delta(model_ref_1="db:984", model_ref_2="ws:704bdd6023a4") 
{
  "concepts": {
    "matched": [/* S, E, I, R: is_equal */],
    "only_in_model_2": [{"name": "V", "identifiers": {"vo": "0001376"}, "context": {"status": "vaccinated"}}]
  },
  "transitions": {
    "matched": [/* t1 infection, t2 progression, t3 recovery: is_equal */],
    "only_in_model_2": [{"id": "vaccination", "type": "NaturalConversion", "concepts": ["S", "V"], "rate_law": "S*nu"}]
  }
}

Step 4: Check the new equations

mira_get_equations(model_ref="ws:704bdd6023a4") 
{
  "equations": [
    "dS/dt = -I*S*beta*(1 - epsilon) - S*nu",
    "dI/dt = E*sigma - I*gamma",
    "dE/dt = -E*sigma + I*S*beta*(1 - epsilon)",
    "dR/dt = I*gamma",
    "dV/dt = S*nu"
  ]
}
Result: Two edits produced an SEIRV model, each as its own workspace version, so the agent can go back to any step. The diff confirms that only V and the vaccination transition are new; the paper's original db:984 is untouched. The agent could also call mira_draw_model_delta to get the same diff as a picture.
🔍 Compare Extraction Methods ▼

Ask: "The same paper was extracted several ways. How much do the resulting models agree?"

Behind the scenes, the AI agent runs the following steps using this MCP server:

Step 1: Score pairwise structural similarity

mira_compare_models(model_refs=["db:984", "db:249", "db:1676"]) 
{
  "similarity_scores": [
    {"models": ["db:984", "db:249"],  "score": 0.25},
    {"models": ["db:984", "db:1676"], "score": 0.75},
    {"models": ["db:249", "db:1676"], "score": 0.5}
  ]
}

Step 2: Check the raw ODEs behind the outlier

db_get_odes(pmid="32706790") 
// SymPy ODE source for each extraction method, including any corrected version,
// so the agent can see where the marker (db:249) extraction diverges.
Insight: The PMC XML (db:984) and MinerU text (db:1676) extractions largely agree (0.75), while the Marker PDF extraction (db:249) differs more. This makes it easy to pick the most trustworthy version of a paper's model.
🧾 Ad-hoc Questions with SQL ▼

Ask: "How big is MIRA-DB? How many papers, models and scenarios does it have?"

Behind the scenes, the AI agent runs the following steps using this MCP server:

Step 1: Read the schema

db_describe_schema() 
## text_references
- id: INTEGER (PK)
- pmid: VARCHAR (NOT NULL)
- title: VARCHAR
...
## mira_template_models
- id: INTEGER (PK)
- ode_ref: INTEGER (FK -> ode_expressions.id, NOT NULL)
- grounded_concepts: JSON (NOT NULL)
...

Step 2: Run a read-only query

db_run_sql(sql="SELECT (SELECT count(DISTINCT pmid) FROM text_references) AS papers, (SELECT count(*) FROM mira_template_models) AS models, (SELECT count(*) FROM scenarios) AS scen") 
{
  "columns": ["papers", "models", "scen"],
  "rows": [{"papers": 2477, "models": 3187, "scen": 3404}],
  "row_count": 1,
  "truncated": false
}
Safe by design: db_run_sql accepts a single SELECT/WITH/EXPLAIN statement, runs it in a READ ONLY transaction with a 15 s timeout, and truncates long values, so the agent can explore freely without risk to the data.

How to Connect

Configure your MCP-compatible AI client to connect to this server:

Terminal 
claude mcp add --transport http miradb https://epimodels.io/mcp

In Claude Desktop, open Settings → Connectors → Add custom connector and enter this URL:

Connector URL 
https://epimodels.io/mcp

Add the server from the terminal:

Terminal 
codex mcp add miradb --url https://epimodels.io/mcp

Or add it to ~/.codex/config.toml (or a project's .codex/config.toml):

~/.codex/config.toml 
[mcp_servers.miradb]
url = "https://epimodels.io/mcp"

Run codex mcp list to check that it was added. The same configuration is used by the Codex IDE extension.

ChatGPT

Open Settings → Apps & Connectors → Advanced settings and turn on Developer mode. Then choose Create, give the connector a name, enter the URL below and pick No authentication. In a chat, enable the connector from the + menu.

Connector URL 
https://epimodels.io/mcp

Developer mode is only offered on some ChatGPT plans, and in a workspace an admin may need to enable it first.

OpenAI API (Responses API)

Pass the server as a remote MCP tool. OpenAI's servers call it directly, so it must be reachable from the internet.

Python 
from openai import OpenAI

client = OpenAI()
response = client.responses.create(
    model="gpt-5",
    tools=[{
        "type": "mcp",
        "server_label": "miradb",
        "server_url": "https://epimodels.io/mcp",
        "require_approval": "never",
    }],
    input="Find a COVID-19 SEIR model for South Africa and simulate it for 100 days.",
)
print(response.output_text)

In the Agent panel, open the ⋯ menu → MCP Servers → Manage MCP Servers → View raw config, and add the server to mcp_config.json (usually ~/.gemini/antigravity/mcp_config.json):

mcp_config.json 
{
  "mcpServers": {
    "miradb": {
      "serverUrl": "https://epimodels.io/mcp"
    }
  }
}

Antigravity uses serverUrl for remote servers, not url, so a configuration copied from another client won't load. Restart the agent session or refresh the MCP server list after saving.

~/.cursor/mcp.json 
{
  "mcpServers": {
    "miradb": {
      "url": "https://epimodels.io/mcp"
    }
  }
}

To run the server yourself over stdio against your own MIRA-DB instance:

Terminal 
python -m pip install "miradb[mcp] @ git+https://github.com/gyorilab/miradb.git"
claude mcp add miradb -- miradb-mcp --db primary

--db names a section of ~/.config/mira/db_config.ini, or primary for the MIRADB_DB_* environment variables. A role with only SELECT grants is recommended.

Connection Details

Endpoint: POST https://epimodels.io/mcp

Transport: Streamable HTTP

Authentication: None required; all database access is read-only

Workspace: Derived ws: models and simulations are kept in server memory and are not persisted
